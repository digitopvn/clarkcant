# #329 browser gate: local-video CSP

**Date:** 2026-10-01 (Asia/Saigon)  
**Status:** blocked pending direction in [#374](https://github.com/digitopvn/clarkcant/issues/374)

## Evidence

The focused Chromium journey placed the local-video view through the host view catalog and fetched the fixture response through the browser route. The `<video>` element then reported `MEDIA_ELEMENT_ERROR` code 4: `Media load rejected by URL safety check`; its `currentSrc` was empty and `networkState` was `NETWORK_NO_SOURCE`.

The current `apps/web/index.html` policy permits `blob:` for `img-src` but omits `media-src blob:`. Under CSP, media therefore falls back to `default-src 'self'`, which rejects the host-created object URL returned by the authenticated `imageObjectUrl` path.

## Constraint and disposition

Issue #329 explicitly says the page CSP remains unchanged. No CSP or media-fetch changes were made. The browser test and temporary WebM fixture were removed rather than retained as a failing test. The implementation's unit coverage for media playback-state validation and coalescing remains, but it does not substitute for the required browser pause journey.

The project must resolve whether to preserve the current CSP and defer local video, permit app-created local blob media only, or specify another design. Until that decision, #329 is incomplete; its video browser criterion and dependent closeout remain open.
