## Status

Tests now **discoverable and runnable** with real keys, but voice utterance processing integration is incomplete (proof-of-concept stage).

## What was fixed

✅ **Test discovery**: Renamed `voice-live.live.spec.ts` → `voice-live-provider.spec.ts` to match Playwright's testMatch pattern

✅ **Security**: `/voice-live/utterance` endpoint now gated by explicit `CC_LIVE_PROVIDER_TEST=1` flag
- Endpoint returns 404 unless flag is set on the node
- Gateway auth (bearer token) required
- Will not be accessible in production

✅ **Infrastructure**:
- `voiceLiveUtterance` service created when `CC_LIVE_PROVIDER_TEST=1`
- Endpoint accepts utterances without 404
- Service accepts queued utterances (stored but not yet processed)

✅ **Playwright config**: Conditionally disables fixtures when `CC_LIVE_PROVIDER_TEST=1` so real providers are used

## What is incomplete (proof-of-concept)

❌ **Voice session integration**: Queued utterances are not yet delivered to the real voice session for processing
- The service queues text utterances but does not process them through the voice session
- This is a deeper integration requiring changes to the voice session lifecycle
- Current implementation is a gating layer proving the endpoint can exist safely

❌ **Real model routing**: Tests cannot prove the model calls `control_app` until utterances reach the session
- Tests fail waiting for the model response that never arrives
- Infrastructure is in place; the voice←→model bridge is future work
